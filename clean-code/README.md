# clean-code

## 概要
`clean-code` は、可読性・保守性・拡張性の高いコードを書くための Skill です。DRY、KISS、YAGNI、SOLID、命名、関数設計、コード構造、リファクタリングの判断を支援します。

## 使う場面
- 新規実装で、明確で保守しやすいコード構造にしたい。
- 既存コードの重複、命名、関数サイズ、責務分割を改善したい。
- コードレビューで、読みやすさや設計原則に沿った指摘をしたい。
- SOLID 原則やリファクタリングパターンを参照しながら改善方針を決めたい。

## 使わない場面
- 要件や仕様が未確定で、まず仕様整理が必要な場合。
- パフォーマンス調査や障害原因分析が主目的の場合。
- 大規模な設計変更や抽象化を、具体的な必要性なしに進める場合。

## 実行フロー
1. 対象コードの目的、変更理由、現在の問題を確認する。
2. 重複、過剰設計、命名、関数責務、コード構造の問題を切り分ける。
3. DRY、KISS、YAGNI、SOLID のどの観点が効くか判断する。
4. 必要な最小変更に絞り、既存スタイルに合わせて改善する。
5. テスト、型チェック、レビュー観点で改善後の読みやすさと振る舞いを確認する。

## 生成・更新する主な成果物
- 可読性と責務分割を改善した実装コード
- 命名や定数化を反映したコード変更
- 重複排除や関数分割を含む小さなリファクタリング
- コードレビューコメントや改善提案

## 注意点
- 偶然似ているだけのコードを無理に抽象化しない。
- 「いつか使うかも」という理由で機能や設定を増やさない。
- 変更範囲を広げすぎず、ユーザーの依頼に直結する行だけを触る。
- コメントはコードの説明ではなく、必要な理由や背景を補うために使う。
