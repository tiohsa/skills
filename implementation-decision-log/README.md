# implementation-decision-log

## 概要
`implementation-decision-log` は、仕様書、計画書、issue、チェックリストなどに沿って実装する際、実装中に発生した判断・逸脱・妥協・検証制約を Markdown に残すための Skill です。元の計画に書かれていない判断を見える化し、レビュー時に後から推測しなくて済む状態を作ります。

## 使う場面
- 仕様書、設計書、計画書、issue、ticket、チェックリストに従って実装する。
- 実装中の未記載判断、解釈、スコープ変更、制約、リスクを保存したい。
- 複数ステップの実装で、曖昧さやトレードオフが発生しそうな場合。
- ユーザーが「判断を記録しながら」「妥協点を残して」などと依頼した場合。

## 使わない場面
- 判断を伴わない小さな機械的編集。
- 実装前の調査・設計計画を残す用途。これは `planning-doc-writer` の担当です。
- 作業後の一般的な changelog を作るだけの場合。

## 実行フロー
1. プロジェクトルートと、実装元になる仕様・計画・ユーザープロンプトを特定する。
2. 実装編集の前に `{project_root}/docs/implementation-decisions/` へログを作成する。
3. `references/decision-log-template.md` を使い、メタデータと初期状態を記入する。
4. 実装中に、仕様の穴埋め、曖昧な解釈、計画からの変更、検証できない点などを都度追記する。
5. 完了前に実装結果を元資料と照合し、漏れた判断や制約を追記する。

## 生成・更新する主な成果物
- `{project_root}/docs/implementation-decisions/YYYY-MM-DD-short-task-slug.md`
- 同名ファイルがある場合は `-2`、`-3` などを付けた Markdown ログ

## 参照リソース
- `SKILL.md`
- `references/decision-log-template.md`

## 注意点
- 判断ログは進捗メモではなく、元資料に明記されていない意味のある判断を残す場所です。
- 仕様からの逸脱は、通常の判断と区別して明記する。
- 検証できなかった項目や残ったリスクも記録する。
- 不確実なまま選んだ場合は、その不確実性も隠さず書く。
