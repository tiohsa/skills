# error-analysis

## 概要
`error-analysis` は、エラーの現象確認から原因特定、修正、再発防止までを体系的に進めるための Skill です。エラーメッセージ、スタックトレース、ログ、再現手順を根拠に、事実と推測を分けて問題を絞り込みます。

## 使う場面
- バグや例外の原因を調査したい。
- エラーメッセージやスタックトレースを読み解きたい。
- 障害や不具合について Root Cause Analysis を行いたい。
- 5 Whys や最小再現で、表面的な修正ではなく根本原因に到達したい。

## 使わない場面
- エラーや不具合ではなく、新規機能の設計が主目的の場合。
- すでに原因と修正方針が明確で、単純な実装だけが必要な場合。
- ログや再現情報を確認せずに推測だけで変更したい場合。

## 実行フロー
1. エラーメッセージ、発生箇所、直前の操作、再現手順を確認する。
2. エラータイプ、スタックトレース、ログから事実を抽出する。
3. フロントエンド、バックエンド、DB、設定、データなど発生範囲を切り分ける。
4. 仮説を立て、一度に一つずつ検証して原因を絞る。
5. 根本原因に対する修正を行い、再現手順とテストで確認する。
6. 必要に応じてテスト追加や設計変更で再発を防ぐ。

## 生成・更新する主な成果物
- 原因分析メモや調査結果
- バグ修正コード
- 再現テストや回帰テスト
- ログ追加、エラーハンドリング改善、再発防止策

## 注意点
- 事実と推測を混ぜない。
- 複数の変更を同時に入れて原因を見失わない。
- ログやスタックトレースを読む前に結論を決めない。
- 最小構成で再現し、余計な要素を取り除いて検証する。
