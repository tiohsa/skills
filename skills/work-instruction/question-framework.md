# 一問一答フレームワーク

## 概要

業務指示作成時に、不明点を効率的に洗い出し解消するための質問フレームワーク。

## 質問カテゴリ

### 1. WHO（誰が）
- 実行担当者は誰か？
- 承認者・確認者は誰か？
- 関係するステークホルダーは？

### 2. WHAT（何を）
- 具体的な成果物は何か？
- 完了の定義は何か？
- 品質基準は何か？

### 3. WHEN（いつ）
- 開始日はいつか？
- 期限はいつか？
- マイルストーンはあるか？

### 4. WHERE（どこで）
- 作業場所の制約はあるか？
- 成果物の保存場所は？
- 共有先は？

### 5. WHY（なぜ）
- この業務の目的は？
- 背景・経緯は？
- 期待される効果は？

### 6. HOW（どのように）
- 具体的な手順は？
- 使用するツール・技術は？
- 参照すべき資料は？

## 質問の優先順位

```
必須: WHAT → WHO → WHEN
推奨: WHY → HOW
任意: WHERE
```

## 掘り下げパターン

### 曖昧な回答への対応

| 曖昧な回答 | 掘り下げ質問 |
|-----------|-------------|
| 「なるべく早く」 | 「具体的な日付で言うと？」 |
| 「適切に」 | 「具体的な基準は？」 |
| 「いい感じに」 | 「サンプルや参考例は？」 |
| 「任せる」 | 「予算・時間の上限は？」 |

### 不明点発見パターン

1. **主語がない**: 誰が実行するか確認
2. **数値がない**: 定量的な目標を確認
3. **条件がない**: 前提条件・制約を確認
4. **例外がない**: イレギュラー時の対応を確認

## 質問終了の判断基準

以下がすべて満たされたら質問フェーズを終了：

- [ ] 成果物が明確に定義されている
- [ ] 担当者が特定されている
- [ ] 期限が具体的に設定されている
- [ ] 作業手順が理解できる
- [ ] 制約条件が把握できている
