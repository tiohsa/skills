# planning-doc-writer

## 概要
`planning-doc-writer` は、実装前の調査、分析、設計メモ、実装方針を `{project_root}/docs/planning/` に保存するための Skill です。コードを変更する前に、何を調べ、どの方針で進め、どう検証するかをレビュー可能な形で残します。

## 使う場面
- 未知のコード領域を調査してから変更する。
- 実装アプローチを比較する。
- 共有挙動、public API、データモデル、ビルド、ワークフローなど影響範囲のある変更を行う。
- バグの原因分析が必要な修正を行う。
- ユーザーが「調査してから実装」「先に計画を残す」「docs/planning に書く」などと依頼した場合。

## 使わない場面
- 一行修正、typo 修正、明白な rename など、計画文書が不要な小さな変更。
- 実装中に発生した判断・逸脱・妥協を記録する用途。これは `implementation-decision-log` の担当です。
- 実装を伴わない通常の質問回答。

## 実行フロー
1. プロジェクトルートを特定する。
2. 関連ファイル、テスト、設定、ドキュメントを調査する。
3. `{project_root}/docs/planning/` を作成または利用する。
4. `references/planning-template.md` をもとに、調査結果、方針、リスク、検証計画を日本語で記録する。
5. 計画ファイルのパスをユーザーに伝えてから、必要に応じて実装へ進む。
6. 実装後、実際の方針が大きく変わった場合だけ計画文書を更新する。

## 生成・更新する主な成果物
- `{project_root}/docs/planning/YYYY-MM-DD-short-task-slug.md`
- 必要に応じた `## Outcome` の追記

## 参照リソース
- `SKILL.md`
- `references/planning-template.md`

## 注意点
- 計画文書は実装前の思考を残すもので、changelog ではありません。
- 調査結果は推測ではなく、読んだファイルや観察した挙動に基づいて書く。
- 検証予定のコマンドやチェックを具体的に記載する。
- 未解決の質問が安全な実装を妨げる場合は、編集前にユーザーへ確認する。
