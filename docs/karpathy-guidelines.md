# karpathy-guidelines

## 概要
`karpathy-guidelines` は、LLM によるコーディングで起きやすい過剰実装、思い込み、不要な変更、検証不足を減らすための行動原則 Skill です。Andrej Karpathy の LLM coding pitfalls に関する観察をもとにしています。

## 使う場面
- コードを書く、レビューする、リファクタリングする。
- 実装前に前提やトレードオフを明確にしたい。
- 変更範囲を小さく保ち、検証可能な成功条件を置きたい。

## 使わない場面
- プロジェクト固有の実装手順やドメイン知識を提供する用途。
- 詳細な設計テンプレート、評価スクリプト、成果物生成が必要な用途。

## 実行フロー
この Skill は成果物生成よりも、作業中の振る舞いを整えるために使います。基本の柱は次の4つです。

1. `Think Before Coding`: 前提、曖昧さ、トレードオフを明示する。
2. `Simplicity First`: 求められていない機能や抽象化を足さない。
3. `Surgical Changes`: 必要な箇所だけを変更し、周辺の不要な改善をしない。
4. `Goal-Driven Execution`: 成功条件と検証方法を定め、確認まで行う。

## 生成・更新する主な成果物
- 固有の成果物はありません。
- 必要に応じて、実装前の前提、短い計画、検証結果を会話や作業ログに残します。
