# refactoring

## 概要
`refactoring` は、外部から見た振る舞いを変えずにコードの内部構造を改善するための Skill です。コードスメルの検出、Extract Function、Move Function、Replace Conditional with Polymorphism などの手法を、小さなステップとテスト確認で適用します。

## 使う場面
- 長い関数、大きすぎるクラス、重複コードを改善したい。
- 機能追加やバグ修正の前に、既存コードを理解しやすくしたい。
- レガシーコードを安全に整理したい。
- Martin Fowler のリファクタリング手法に沿って段階的に改善したい。

## 使わない場面
- 外部仕様や振る舞いを変える機能追加が主目的の場合。
- テストや検証手段がなく、変更の安全性を確認できない場合。
- 関係ない周辺コードまでまとめて整理したいだけの場合。

## 実行フロー
1. 現在の振る舞いとテスト状況を確認する。
2. コードスメルを特定し、適用するリファクタリング手法を一つ選ぶ。
3. 小さな変更だけを行い、外部から見た動作を変えない。
4. テストを再実行し、振る舞いが維持されていることを確認する。
5. 必要な場合だけ次の小さなリファクタリングを繰り返す。

## 生成・更新する主な成果物
- 構造を改善した既存コード
- 抽出した関数、クラス、値オブジェクト
- 条件分岐や責務配置を整理した差分
- リファクタリングの安全性を支えるテストや検証結果

## 注意点
- リファクタリング中に外部仕様を変えない。
- 一度に複数の改善を混ぜない。
- テストがない場合は、先に安全確認の方法を検討する。
- 依頼範囲外のデッドコードや設計問題は、勝手に削除せず必要なら報告する。
